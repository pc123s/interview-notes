## 一、jieba分词原理

jieba分词器是目前一个比较先进的分词工具，其中主要有词性标注、分词、新词发现等一系列功能。

## 1、分词

jieba 的分词分为有向无环图的分词和HMM分词两个部分，整个jieba 的分词过程如图1所示：

![](.\img\1.png)

jieba分词主要使用词典，这里介绍一下DAG模型。

首先DAG是基于字典来进行分词寻路的，基本原理是字典+动态规划，假设字典为

```python
这
是
怎么
回事
怎么回事
```

这些词，那么我们对这是怎么回事进行分词，通过DAG扫描以后可以得到

```python
{0: [0], 1: [1], 2: [2, 3, 5], 3: [3], 4: [4, 5], 5: [5]}
```



代表共有5条路可以选择。即

- 0/1/2/3/4/5：“这/是/怎/么/回/事”
- 0/1/2/3/45：“这/是/怎/么/回事”
- 0/1/23/4/5：“这/是/怎么/回/事”
- 0/1/23/45：“这/是/怎么/回事”
- 0/1/2345：“这/是/怎么回事”

那么怎么选择呢，始终在对比成词的概率，比如分为 怎么/回事和怎么回事对比

```python
max(p怎么)*p(回事)，p(怎么回事))
```

概率等于词语的频率/总的词频

上面用DAG找出的词语的概率如下：

```json
{6: (0, 0), 
 5: (-7.202281913155641, 5), 
 4: (-10.825651663389609, 5), 
 3: (-19.402701776548223, 3), 
 2: (-16.81294083908711, 5), 
 1: (-21.135895301480033, 1), 
 0: (-26.57214667475555, 0)}
```

 上面结果需倒着看，对应分词方案：0/1/2345（“这/是/怎么回事”） 

注意，jieba进行分词时采用的是后向分词，因为汉语的主要重心在后方，所以采用从后向前扫描，分词后的结果更精准。

## 2、HMM

jieba除了分词以外，还会对词语进行HMM算法进行划分。HMM即隐马尔可夫链，使用verterbi算法加隐马尔可夫链的形式进行分词。

具体的原理如下：

（1）HMM的三个假设

假设1：转移状态只依赖于前一个状态

P(Status[i]|Status[i-1],Status[i-2],… Status[1]) = P(Status[i]|Status[i-1])

假设2：

P(Observed[i]|Status[i],Status[i-1],…,Status[1]) = P(Observed[i]|Status[i])

状态值之和当前观测值有关

（1）HMM将自己分为5个元数组

StatusSet: 状态值集合
ObservedSet: 观察值集合
TransProbMatrix: 转移概率矩阵
EmitProbMatrix: 发射概率矩阵
InitStatus: 初始状态分布 

- statusSet:状态矩阵集合，主要分为{B,M,E,S}四个状态，B 代表开始(begin)，E代表结束（end），S代表单字(single）M代表中间（Middle）

  ```
  B:XX
  M:XX
  E:XX
  S:XX
  ```

- 观察值集合为就是所有汉字(东南西北你我他…)，甚至包括标点符号所组成的集合。

  状态值也就是我们要求的值，在HMM模型中文分词中，我们的**输入**是一个句子(也就是**观察值序列**)，输出是这个句子中**状态值的集合**。 

- 初始状态概率分布（InitStatus ）

  如：

  ```text
  B  -0.26268660809250016
  E  -3.14e+100
  M  -3.14e+100
  S  -1.4652633398537678
  ```

  数值是对概率值取【对数】之后的结果(可以让概率【相乘】的计算变成对数【相加】)。其中-3.14e+100作为负无穷，也就是对应的概率值是0。

  也就是句子的第一个字属于{B,E,M,S}这四种状态的概率。

- 转移概率矩阵（TransProbMatrix ）
  转移概率是马尔科夫链。Status(i)只和Status(i-1)相关，这个假设能大大简化问题。所以，它其实就是一个4x4(4就是状态值集合的大小)的二维矩阵。矩阵的横坐标和纵坐标顺序是BEMS x BEMS。(数值是概率求对数后的值） 

  ```
  B->M S E 概率
  M->E 概率
  S->B 概率
  E->S -> M 概率
  ```

- 发射概率矩阵（EmitProbMatrix ）
    【观察值独立性假设】
    P(Observed[i], Status[j]) = P(Status[j]) * P(Observed[i]|Status[j])
    其中，P(Observed[i]|Status[j])这个值就是从EmitProbMatrix中获取。 

```
发射矩阵是状态到observe的过程
B->所有汉字 
E->所有汉字
S->所有汉字
E->所有汉字
```



（2）算法计算过程及例子

```python
这五元的关系是通过一个叫Viterbi的算法串接起来，ObservedSet序列值是Viterbi的输入，而StatusSet序列值是Viterbi的输出，输入和输出之间Viterbi算法还需要借助三个模型参数，分别是InitStatus, TransProbMatrix, EmitProbMatrix。

以下句子为例：

小明硕士毕业于中国科学院计算所

定义变量

二维数组 weight[4][15]，4是状态数(0:B,1:E,2:M,3:S)，15是输入句子的字数。比如 weight[0][2] 代表 状态B的条件下，出现’硕’这个字的可能性。

二维数组 path[4][15]，4是状态数(0:B,1:E,2:M,3:S)，15是输入句子的字数。比如 path[0][2] 代表 weight[0][2]取到最大时，前一个字的状态，比如 path[0][2] = 1, 则代表 weight[0][2]取到最大时，前一个字(也就是明)的状态是E。记录前一个字的状态是为了使用viterbi算法计算完整个 weight[4][15] 之后，能对输入句子从右向左地回溯回来，找出对应的状态序列。

B:-0.26268660809250016
E:-3.14e+100
M:-3.14e+100
S:-1.4652633398537678

且由EmitProbMatrix可以得出

Status(B) -> Observed(小)  :  -5.79545
Status(E) -> Observed(小)  :  -7.36797
Status(M) -> Observed(小)  :  -5.09518
Status(S) -> Observed(小)  :  -6.2475

所以可以初始化 weight[i][0] 的值如下：

weight[0][0] = -0.26268660809250016 + -5.79545 = -6.05814
weight[1][0] = -3.14e+100 + -7.36797 = -3.14e+100
weight[2][0] = -3.14e+100 + -5.09518 = -3.14e+100
weight[3][0] = -1.4652633398537678 + -6.2475 = -7.71276

注意上式计算的时候是相加而不是相乘，因为之前取过对数的原因。

具体可以演示为
初始化状态->小(最大值)<得到状态1>->转移矩阵状态（状态1->状态2）->发射矩阵状态（状态2->字）->转移矩阵状态（状态2->状态3）->发射矩阵状态（状态3->字） 循环
```

计算完成后进行回溯操作。

```
weight[1][14] = -102.492;
weight[3][14] = -101.632;
所以 S > E，也就是对于路径回溯的起点是 path[3][14]。
回溯的路径是:
SEBEMBEBEMBEBEB

倒序一下就是:
BE/BE/BME/BE/BME/BE/S

所以切词结果就是:
小明/硕士/毕业于/中国/科学院/计算/所
```

## 二、项目的改进点

1、python版

从算法原理进行jieba的分词思路改进，改为字典树+最大后向分词来提升分词的速度。

前向最大匹配分词算法：将输入的字符按照词典中词的最大长度分割，然后将分割的子字符串与词典匹配，如果匹配成功则使用余下的字符串继续匹配。否则，将子字符串从末尾去除一个字符，再进行匹配，知道满足条件为止。

后向最大匹配: 与前向最大匹配类似，只不过前向最大匹配是从左到右，而后向最大匹配是从右到左。

句子：我们经常有意见分歧
词典：[“我们”，“经常”，“有”，“有意见”，“意见”，“分歧”]

例1：前向匹配

开始匹配:
①【我们经常有】 ×
【我们经常】 ×
【我们经】 ×
【我们】 √
②【经常有意见】 ×
【经常有意】 ×
【经常有】 ×
【经常】 √
③【有意见分歧】 ×
【有意见分】 ×
【有意见】 √
④【分歧】 √
分词成功！！！！

例 2：后向匹配

开始匹配:
①【有意见分歧】 ×
【意见分歧】 ×

【分歧】 √

【常有意见】 ×
【有意见】 √

例3：后向字典树

后向字典树是指将词语按照后向切分的方式存入字典之中，形成后向字典树，这样进行匹配时，一旦没有匹配到子集则匹配结束，加快匹配效率。

如：英雄联盟这个词

后向字典树为：

盟

联盟

雄联盟

英雄联盟

那么在匹配我喜欢英雄联盟这款游戏时，如果发现子集没有匹配到，则整个的匹配结束。



对python版分词的改进在于，首先将分词的方法由动态规划改为了最大后向分词，其中采用后向字典树的方式加快字符串的匹配效率，并且采用pyd进行部分函数的加密，加快了字符串的匹配效率。进行改写后的程序供内部算法人员使用。目的是确保和c++sdk的一致性。

2、c++版

​	在python的基础上，我对c++的cppjieba也进行了改写。主要的算法思路和python版相似，也是将动态规划的分词算法改为后向分词算法，开发一版快速的cppjieba算法，与之前的算法程序相比，新的算法速度提高了100%，分词时间缩短了一半。

3、HMM模型的改进

​	jieba的hmm模型是根据通用的数据集语料训练的。分词结果中很多未成词的词语都是通过HMM算法进行拼接，主要是单字，所以这一算法的结果对新词的拼接十分重要。这里我收集了涉案、情感等领域的专用文本，采用jieba的原始分词加专用词典的方式进行分词，将分词的结果进行训练得到最新的hmm模型成为各个领域的专属hmm模型而用来提升分词的准确率。

​	使用c++代码编写sdk，兼容了之前改进的分词技术，并在其中添加了正则固定模块的筛选（如微信中 xxx加入了群聊，xxx进入了微信群等特定模板的句子），添加了停用词和表情符的筛选函数，使用cppjieba的字典树，将其转为后向字典树进行筛选，用于在项目中提升模型的推理速度。并且sdk编写为exe文件提供给中心和其他人员进行调用。



## 三、面试的问题

### 1、你是怎么优化分词算法的。

首先，我是先调研目前已有的分词算法的框架，对开源的分词算法进行测试，看看分词算法的速度和精度，看看有没有比jieba更好的工具能够平替，如果没有那有没有可以借鉴的算法能够实现。从调研结果看，jieba 的分词算法仍然是最优的。

然后，我选择在jieba分词本身的算法层面去优化，jieba分词是以字典+DAG（有向无环图）的方式去分词，我对分词进行拆分计时，发现DAG的耗时最多，于是采用了后向字典树+后向分词的算法代替DAG，然后利用自有的分词材料去优化HMM，减轻由于DAG改动带来的误差。

### 2、HMM的原理

HMM是隐马尔可夫链，在jieba中主要是使用统计的方式去将单字形成所需要的词语，其本质是一个序列标注的问题。这个具体用到了veterbi算法，使用了初始化矩阵、转移矩阵、发射矩阵去求得分词中每个字的序列标注标签。

### 3、能说下hmm和verterbi算法吗，时间复杂度

verterbi算法的前提是路径是全路径的，即从开始到结尾所有节点都是默认连接的。其主要过程为，从开始节点，到下一节点，每次都动态的选择其中的最短路径作为最优节点，直到循环的到终点。其时间复杂度为O（nm）,n为节点的长度，m为可以选择的路径点数。verterbi主要是针对连续序列的一种优化。
